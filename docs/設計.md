# Sunlit Path 設計メモ

最終更新：2026-11-17（v0.24）。アプリを直す人（Claude・Codex）は、作業の前にここを読む。

## 文法フォーカス（v0.23〜）

ストーリーの道とは別に、1つの文法を集中して練習するページ。学校版（肢体不自由部門の生徒）が主な対象。

### 作り方の決まり（運営者の指示）
1. **しくみはまとめて見せ、練習は使い方ごとに分ける。**
   - 例：現在完了の「完了・経験・継続」は、①しくみ では3つ並べて見せてよい。
   - 演習（基本文・作る・確かめる・自分の文）は、使い方ごとに別立てにする。
2. **似ている文法との違いを、丁寧に説明する。**
   - 例：過去形と現在完了、現在形と現在完了（継続）、have been to と have gone to、現在進行形と現在完了進行形。
   - 日本語にするとどちらも同じ（「～した」「～している」）になって迷うところを中心にする。
   - 「くらべる」は話題ごとに分ける。1つの話題に「ならべた例文 → 違いのポイント → たしかめる問い」を入れる。
3. **1つずつの個別性を大切にする。**
   - 意味が近い形でも、それぞれの意味・使う場面・言いかえ・まちがえやすい所を別々に作る。
   - 今後の例：助動詞の can と be able to、will と be going to、must と have to。
   - 「同じ意味」とまとめず、違うところ（使える時制、話し手の気持ち、前から決めていたかどうか、否定にしたときの意味のずれ など）を説明する。

### 画面の流れ
- ① しくみ（全体）：形、使い方ごとのカード（時間の線・例文・目印）、注意のカード。カードから、その使い方の練習へ進める。
- ② ③ ④ …（使い方ごと）：次の5つ。
  1. 意味と形：普通の文、否定の文、疑問の文、答え方。目印の言葉と、その置き場所。ここに注意。
  2. 基本文：聞く・音読（録音）・音声入力・タイピング・手書き。
  3. 作る：並べる（使わない語が1つまじる）と、選ぶ。
  4. 確かめる：その使い方だけの問い。
  5. 自分の文：Kai の問いに答える。点検では、形とその使い方の目印を見る。
- 見分ける：使い方をまぜた問い。
- くらべる：似ている文法との違い（話題ごと）。
- まとめテスト：使い方ごとの点数と「くらべる」の点数を出す。まちがえた所へ「もう一度」で戻れる。

### データの形（index.html の `GRAM`）
- 1つの文法の項目：`{id, title, sub, form, formNote, intro, warn?, parts:[…], sortQ, sort:[…], comps:[…], check, test:[…]}`
- `parts`（使い方）の中身：`{key, name, color, mean, svg, ex, forms, signals, points, base, make:{order, pick}, chk, own, marks}`
- `comps`（くらべる）の中身：`{title, lead, pairs:[[見出し, 色, 英文, 訳, 説明]], points, qs}`
- `test` の6つ目：使い方の key か `"くらべる"`。結果の集計に使う。
- 文法を足すときは、`GRAM` に1項目を足すだけでよい。手順のボタンは `parts` の数から自動で作る。

### 英文と問いの決まり
- Kai の設定（プロジェクトの「Sunlit_Path_Kaiの設定.md」）とくい違わないように書く。
- 文法の正しくない文は、お手本として見せない。まちがった形は、選ぶ問いの選択肢にだけ出す。
- 選ぶ問いは、日本語の訳と場面から、答えが1つに決まるようにする。アメリカ英語なら正しくなる選択肢は避ける。
- 説明の日本語は、高校生向けなので普通の漢字で書く。
- 英語と説明は、書いた人とは別の担当が点検してから入れる。
